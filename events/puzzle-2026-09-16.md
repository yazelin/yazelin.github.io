## 當晚實際做了什麼

現場從零談出一個劇情，整段交給 Agent，它在 Larch 上建卡、生圖、配語音，做出一款 32 個節點的解謎小說。做完當場試玩，抓到背包的 bug，退回去叫它修，修到能玩之後發佈、勾挑戰賽、交件。

成品是《晚霞舌尖最後的刺痛》：調酒師留下一杯毒酒與一張便條，玩家要把那杯「初遇的滋味」調出來。兩個結局都是悲劇導向，一個殘酷直白、一個悽美。立繪、語音、主題曲都是 AI 生的。

## 這一晚最有用的一招

Agent 對背包插件的理解不夠深，會自己補出看起來像背包系統的東西，格式其實是錯的。症狀很好認：取得道具的時候，道具底下那層框整片黑，一大塊擋在畫面中間。

解法是給它一份真的。到遊戲作品區把官方範例「背包功能教學」remix 一份到自己的專案，複製那個專案的 ID 貼給 Agent，叫它照這一份的格式做。它會自己去抓、比對出正確格式、照抄。

**手上有一份長得對的東西，給它比描述它有用。** 當晚等 Agent 的時候順手做的那個單頁播放器，用的是同一招：把之前寫好的另一個網頁貼給 AI，叫它照那個做。

## 當晚踩到的坑

| 症狀 | 真正的原因 |
|---|---|
| 畫面寫著收進背包，打開背包卻是空的 | 它沒有真的寫進背包。後面那張卡設了「身上要有這件道具才能選」，於是對話走不下去 |
| 改成自動取得之後，用完道具畫面就卡住 | 它換的修法不對。方向錯了就講方向，不要只回報症狀 |
| 取得道具那層框整片黑、尺寸不對 | 沒給它官方範例，它自己補的格式 |
| 上傳久到以為壞了 | 一分鐘一張圖。九張圖傳了六分鐘，專案節點數在那之前都是 0 |
| 立繪講完話該消失卻一直卡在畫面上 | 當晚它改不完，最後人自己手動改掉比等它快 |

## 試玩要走的六格

回饋只講「第幾格、卡在哪張卡、畫面上看到什麼」。不要講「感覺怪怪的」，Agent 修不了感覺。

1. A 撿 ① → B 用 ① 撿 ② → C 用 ② → 通關，這條走得通
2. 先去 C 什麼都沒帶，有提示，不卡死
3. 去 B 沒帶 ①，一樣有提示
4. 打開背包真的看得到那件東西，名稱跟畫面一致，圖不重複
5. 通關後圖鑑多一張
6. 沒通關的結局能回標題重來

當晚就是**第 4 格**擋住流程的，一路修到收工。第 5、6 格時間不夠沒走到。

## 解謎規格表

這張表當晚沒有逐格填在螢幕上，實際做法是把同樣這些欄位在聊天裡跟 AI 談出來。回家自己做的時候照表填會比較快，粗體的一定要人填。

**一、規模（先鎖死）**

| 項目 | 上限 |
|---|---|
| 遊戲時間 | 5 到 10 分鐘 |
| 場景 | **3 個**（A、B、C） |
| 角色 | **最多 2 個有立繪的**，旁白不算 |
| 物品 | **3 件**，一件在 A 撿、一件在 B 撿、一件在 C 用 |
| 卡片 | 25 張以內 |
| 結局 | 1 個通關加 1 個沒通關，沒通關的也要能重來 |

當晚那部做到 32 個節點，超過這張表寫的上限，所以跑了 70 分鐘。節點數決定它要跑多久：21 個節點明顯快，29 到 32 個都要一小時以上。

**二、劇情（這一段人來填）**

- **一句話題材**：誰、在哪、要做到什麼才能離開。
- **通關那一刻玩家明白了什麼**：謎案是倒著寫的，先寫這一句。
- **場景 A**：名稱、背景一句描述、可以點的東西、撿到的物品 ①。
- **場景 B**：名稱、背景一句描述、用物品 ① 打開什麼、撿到的物品 ②。
- **場景 C**：名稱、背景一句描述、用物品 ② 通關；缺物品時的提示句。
- **要回頭的地方**：哪一條線索要回 A 或 B 才拿得到，這就是官方說的場景往返。
- **角色**：名字、一句識別特徵（髮型、髮色、一件固定配件）、跟玩家的關係。

還有一層最容易漏掉：**讀完的人會感覺到什麼、你想讓他理解什麼。** 把這一層也講給 AI，它會把那件事埋進謎題與結局，而不是只把物品排一排。

**三、規則（貼給 Agent 的那幾條）**

1. 物品用背包插件收，撿到就進背包，不消耗的標「重要物品」。
2. 走錯場景不會死：沒東西可用時給一句提示，把玩家送回選場景的那張卡。
3. 每個場景都從「選場景」那張卡進出，來回不丟進度。
4. 兩個結局都標成結局；通關結局解鎖一張 CG 進圖鑑。
5. 先交無語音版，播一遍確認三件物品的順序對了，再配音。試玩用預覽連結（有時效），確定了再發佈拿市集網址。
6. 卡片文字用正體中文、全形標點。
