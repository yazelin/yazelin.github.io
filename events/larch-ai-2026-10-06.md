> **10/6（二）20:00 開播。** 臨時快閃加開場，連結當天在社群公布，往下拉加入社群就會收到。

很多人在 9 月的直播之後開始嘗試用 AI 寫視覺小說。大家常問我：「亞澤，為什麼我叫 AI 改一句話，在線上等半天？」「改沒幾次突然整台卡住報錯？」「要跟 AI 說哪句台詞唸錯，光找卡片 ID 就想放棄……」

線上改卡片的 API 本來就有保護機制：連續改 7 到 8 次就會觸發 HTTP 429 強制罰站 17 秒冷卻。如果每次改動都要上傳雲端再手動重新整理網頁，改完一部作品至少要多等半小時以上，心流全被打斷了。

我平常在做《格莉奇與黑洞先生》或《咒泉鄉的白帝城》時，在開發期根本不是在線上等。我全都在本機跑一個自己寫的預覽外殼，今天早上正式把這套工具開源釋出（[yazelin/larch-preview](https://github.com/yazelin/larch-preview)）。

## 這晚會走過的路

- **實測撞牆揭密**：為什麼線上連續改幾次會被鎖 17 秒？現場看 HTTP 429 報錯。
- **50 次連續更新壓測**：本地 50 秒跑完，線上超過 200 秒（其中近 2 分鐘在冷卻罰站）。
- **1 秒極速熱重載**：左邊 VS Code 存檔，右邊瀏覽器 1 秒自動換句，而且視角牢牢停在原本那張卡片的那一句。
- **不用 AI 也能跑**：純手動 4 步驟，用 VS Code 自己寫對白，一枚松果幣與 Token 都不用花。
- **F 鍵截圖即時回饋**：預覽時按「F」鍵自動截圖並記錄卡片 ID，讓 Agent 讀檔精確把唸錯的字修掉。
- **完工整包推上雲端**：本地無限次迭代，最後只要 1 次呼叫整包替換，不撞 429。
- **跨平台安裝教學**：macOS、Linux 與 Windows 原生 PowerShell（免 WSL、免管理員權限）。
