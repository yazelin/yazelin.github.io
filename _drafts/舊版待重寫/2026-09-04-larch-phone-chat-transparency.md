![通知橫幅直接浮在深夜辦公室的場景上，底下沒有黑](https://github.com/yazelin/yazelin.github.io/releases/download/blog-images/2026-09-04-larch-phone-chat-transparency.webp)

9 月 3 日凌晨兩點五十六分，我把一句話寫進插件的設定提示裡：

> 播放器把整層插件畫成不透明深色，真透明做不到。

那句話是量過才寫的。Larch 播放器的 `fullscreen` 插件層，iframe 跟外框當時都是不透明的 `rgb(10,11,14)`，插件蓋在場景前面就是一片深色。想要「手機浮在遊戲場景上」的效果只剩一條路：把插件自己的背景圖設成跟該場景同一張圖，肉眼看過去就接起來了。我還替這個障眼法配了一顆旋鈕，壓暗百分比，讓作者自己調那張假背景要壓多黑。

隔天晚上八點二十五分，官方把插件透明做出來了。

這支插件叫「格莉奇-AI對話手機」，是 [Larch](https://larch.ink/) 視覺小說平台的插件，我寫給在上面做遊戲的作者用。劇情走到手機卡，畫面出現一支手機，玩家用 LINE 式介面跟劇中角色傳訊息，回覆由 AI 即時生成。另一張「收到訊息」卡不開手機，通知橫幅滑下來、把作者寫好的訊息塞進對話串，停幾秒自動繼續，之後打開手機訊息就躺在裡面。整段對話存在專案變數裡，下一張手機卡接得下去，也一起餵給 AI。預設示範角色是[格莉奇]({% post_url 2026-08-05-glitch-os %})。

所以 9 月 4 日那個晚上，我從 v0.3.2 一路推到 v0.3.4。大半力氣花在把自己下過的那個結論收回來，新功能只佔一小塊。

## 收回一句話，比寫下它麻煩

官方那次改動我實測兩層。新版播放器四個建 iframe 的地方都加上了 `background:transparent`；我再到市集正式版上量一次，iframe 是 `rgba(0,0,0,0)`，外框 `vn2-configurable-frame` 是 `rgba(10,11,14,0)`，顏色沒變、alpha 變成 0。另外 `pluginPresentation:"fullscreen"` 的外框透明度預設本來就是 0，邊線在 opacity 0 的時候也自動變透明。所以壓暗設 0、背景圖跟背景色都留空，遊戲場景就真的透出來。要不要收回那句「做不到」，是我自己拍的板。

麻煩的在後面。那句話不只寫在一個地方，它散在十段中英設定提示、卡片 HTML 的註解、README 的已知限制，還有我給平台的需求清單裡。v0.3.2 我掃掉八段提示，二十八分鐘後又補掃兩段：「收到訊息」卡的壓暗跟背景圖，中文改了、英文那半還留著舊說法。這些提示段落的數量我是一段一段數的，沒有抓大概。

這件事值得記一下。寫一個 workaround 的成本從來不在寫它那幾行，在它會往文件、提示、註解裡繁殖。作廢的那天要一段一段挖回來，而且第一輪一定會漏。

## 透明開了，灰底才現形

v0.3.2 推完六分鐘，我在編輯器按播放，背景圖明明拿掉了，卡片還是先灰一下才跳出通知。

原因不在卡片設定，在兩支卡的 CSS。它們各自在 `body` 上寫死了一層深色紗（「收到訊息」35%、手機 55%），那是頁面載入當下就畫的；真正的壓暗值要等 `larch:init` 把設定送到才由 JS 覆寫。中間那一小段時間，畫面上是那層寫死的紗。以前插件層本來就不透明，這一閃看不出來，官方把透明開了它才現形。

改法是 `body` 預設 `background:transparent`，壓暗一律等 init 到了再補，加 0.3 秒過渡讓有壓暗的卡片不會硬跳。程式碼、那幾支驗收腳本，還有負控制的量法，都是 AI 寫的。驗收用負控制量：把卡片放在純綠底 `#12b76a` 上，模擬 init 永遠送不到的最壞情況，舊版量到 RGB (14,123,75)，被灰紗蓋掉；新版量到 (18,183,106)，正好等於那片純綠，代表完全透明。這三組 RGB 都是實際跑出來的輸出，沒有一個是補上去湊的。

同一顆旋鈕還有一個決定，我刻意沒做。壓暗的預設值是 55。透明開了之後，照理說預設該改成 0，新卡片拉出來就是透明的，最合直覺。

我沒改。這顆旋鈕的預設值會回頭咬到別人：沒存過 `dim` 的既有卡片，播放時吃的就是插件定義裡的預設值。改預設等於改到其他作者已經發佈出去的作品外觀，他們什麼都沒動，畫面卻變了。新的說明文字寫清楚「設 0 就透明」，剩下的讓作者自己決定。

## 黑底的真因不在我的 CSS

晚上十點，卡片還是黑的。

背景圖拿掉了，壓暗歸零了，播放起來還是一整片黑。我一開始懷疑自己的 CSS 沒清乾淨，或是官方的透明只在某些路徑上生效。兩個都猜錯。實測出來的兩件事都不在卡片這邊。

第一，編輯器的色彩選擇器沒有「空」這個狀態。只要卡片設定被開過一次，原本沒設定的 `bgColor` 就被寫成 `#000000`，卡片照自己的規則老實鋪一整片黑。我讀 Larch 的板子確認過，DEMO 的 `n2` 真的存著 `#000000`。

第二件才是真正卡住的：**Larch 存 `pluginValues` 的時候會把空字串丟掉。**我送 `""` 進去想把那個黑清掉，讀回來的時候鍵直接消失、舊值原封不動留著。送 `"none"` 才寫得進去。

所以我繞開色票。`bgColor` 從 `kind:"color"` 改成 `kind:"text"`，標籤直接寫成「背景色（留空＝透明）」，兩支卡把 `none`、`transparent`、`無`、`-` 一律當成沒有顏色，`bgImage` 同樣處理。換成文字欄這個決定是我定的，換下去的程式碼是 AI 寫的。DEMO 三張卡改送 `none`，讀回來驗證三張都是 `none`。

色票沒辦法表示「不要顏色」這句話，我連英文提示都寫上去了。將來一定有人問，為什麼別人家都是色票，這一格是文字欄。

## 兩個 id 才叫授權

同一天官方還加了一道安全性檢查，把插件的第二種 AI 模式整條弄死。

插件有兩個 AI 上游。一個是我請客的中繼，金鑰放在 Worker 的 secret 裡；另一個是「用我的 Larch 點數」，作者拿自己的平台點數餵 AI，一回合一點、零金鑰，靠市集發佈 id 當通行證。9 月 4 日起，官方 AI 只服務「發佈快照裡真的有一張 AI 對話卡」的作品，而中繼送過去的 `cardId` 一直寫死成假值 `"phone-chat"`，所以第二條路整條斷了。

最花時間的是錯誤訊息。我拿快照裡真實存在的 `n1`、`n5`，跟亂打的 id，三種都回同一句：

> 這個公開作品沒有授權這項 AI 操作

它不會說缺的是哪一樣。

v0.3.3 我加了一個設定欄位「官方 AI 卡 id」。我在版子上放一張官方的「AI 對話」卡當授權憑證，不接任何一條邊，玩家永遠走不到，再把那張卡的 id 填進去。中繼那邊我拿掉 `"phone-chat"` 這個預設值，缺 `cardId` 直接回 400 講清楚。所以這個模式要填兩個 id。

填之前還有一件事要先確認：發佈會不會改寫卡片 id。如果會，`n9` 就得等發佈完再回頭查一次真的 id。我讀市集快照端點比對過，發佈後 `project.nodes` 與 `project.boards[].nodes` 的 id 跟專案端一模一樣（`n1` 到 `n8`）。這幾個 id 是一個一個對出來的，沒有一個是補上去湊的。先填、再發佈，是安全的。

當晚最後一筆 commit，我只寫了一條提醒。那張 `n9` 授權卡一旦躺在已發佈的快照裡，授權就是對外開放的。我實測過這道授權的邊界，結論是只要卡還留在快照裡，扣的都是我的點數，跟我自己的卡片有沒有走到第二種模式無關。怎麼繞的細節不寫在這裡。

這張卡留還是拿掉，是我自己的決定。我的額度目前免費無限到 2027 年，所以現在留著。到期那天要做的事我已經寫進 repo 的 NEXT：把 `n9` 拿掉重新發佈，等於撤銷授權。這種「現在沒事、到期會出事」的東西，當場寫進待辦最保險，記憶靠不住。

## 送審那件小事

晚上十點零八分，我在後台把插件名稱改成「格莉奇-AI對話手機」。產生插件定義的 `gen_plugin.py` 裡還寫著舊的「格莉奇手機」，再送審一次就會把後台的命名蓋回去。

我用公開的 `GET /api/plugins` 對過線上那一筆，除了版號跟這個名字，`nameEn`、作者、授權、定價、中英描述全部一致，所以只有這一欄要改。這個對照法我也一起寫進 README 了，下次不用重想。

十點十二分，我把 0.3.4 送出去審。
