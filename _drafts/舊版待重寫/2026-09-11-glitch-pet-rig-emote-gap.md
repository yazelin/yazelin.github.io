![舊靜態圖與新 2D 骨架的四個表情對照，上排是舊圖，下排是骨架](https://github.com/yazelin/yazelin.github.io/releases/download/blog-images/2026-09-11-glitch-pet-rig-emote-gap.webp)

換上會動的桌寵之後，我做的第一件事是量她的表情，結果被自己打臉：開心跟當機這兩個表情，臉上的變化比原本那張不會動的圖還小。

要不要把她從「幾張表情差分圖」改成「一副會動的骨架」，是我自己拍的板，所以這一巴掌也只能算我頭上。如果你正要把一個角色這樣換過去，我這一輪踩到的東西大概會原封不動等著你，包括這個跟直覺相反的結果：會動不等於表情比較清楚。骨架本身怎麼做的寫在[前一篇]({% post_url 2026-09-10-glitch-2d-regenerate-dont-warp %})，這篇不重講。站是[格莉奇OS]({% post_url 2026-08-05-glitch-os %})，右下角常駐的那位就是桌寵。

## 半夜一點多，我把她換成活的

9 月 11 日凌晨 1 點 23 分那筆 commit 把她從換圖改成活的。`glitch2d/` 是從 [glitch-2d](https://github.com/yazelin/glitch-2d) 抄過來的執行期副本：engine 四支模組（motion／geometry／renderer／audio）加一份 `rig.json`，貼圖轉成 WebP 放 `images/glitch2d/`，8 張從 PNG 的 8.2 MB 壓到 0.7 MB。這包執行期跟把它掛上站的那段程式都是 AI 寫的，我出的是規格。

canvas 我要求直接掛在桌面的 DOM 裡，沒有包 iframe。桌寵頭上那顆對話泡、點下去開聊天的命中區、當機時的抖動與色偏，全部是站上原本就有的 CSS 與事件，隔一層 iframe 就全要重做一遍。

退路我要三層，而且每一層都要實測過。WebGL 建不起來就換 Canvas 2D（失敗的 context 會把 canvas 的型別鎖死，所以要先換掉節點，站上顯示的是 `mountPet()` 回傳的那一張）；`rig.json` 或貼圖載不到，桌寵就維持原本的靜態立繪不動。她是常駐的，所以畫面壓在 32fps，捲出視窗或分頁切走就不畫。

## 早上起來，她縮水了

凌晨掛上去的時候我只給 canvas 寫了 `height:100%`，等於把她塞進 `#pet` 容器裡。那個容器桌機 46vh、手機 34vh，兩個斷點都把她縮掉了，桌機她的高度只剩舊版的 27%。這條跟骨架沒關係，是我自己改壞的。

舊版根本不是這樣做的。舊版是兩套：桌機讓 img 用原始尺寸 598x1536 溢出容器，做出「超大半身、腳在畫面外」的效果；手機才用 `min(62vh,520px)` 收成小全身。

修法是讓 canvas 照同一套走。`--pet-figure` 定她的身高，canvas 依她佔畫布的比例（95.95%）反推高度再往外推，`#pet` 的寬度固定成舊圖的寬度，命中區與泡泡那些百分比才不會跟著跑。位移是量出來的：拿她胸前那塊 ERROR 布標，在舊版跟骨架版之間對到中心重合。

版型這一修，還有後面那幾支 Playwright 量測腳本，都是 AI 動手，我出驗收標準跟看數字（1440x900 與 390x844，動畫停掉）：

- 桌機：頂端舊 417 新 415、螢幕上可見高舊 483 新 485、右緣距視窗右舊 150 新 151、ERROR 布標寬舊 70 新 71、布標中心 x 舊 1088 新 1087
- 手機：頂端舊 483 新 483、可見高舊 361 新 361、右緣距視窗右舊 0 新 0
- 旁邊的黑洞先生兩個斷點都沒被影響，桌機 734x1484、手機 257x520，跟舊版相同

剩下的差是姿勢不同，舊圖那張是舉手揮手，手臂會多佔寬度。

## 版型對齊了，我才敢開始量

表情能不能「看出來」，我不想用感覺講。怎麼驗才算數是我定的，量法很土：同一個視窗、同一塊臉的矩形、把動畫停掉，每個表情跟平常臉比平均像素差。舊圖與骨架用同一塊矩形，因為版型剛剛才對齊過。

第一次量出來我自己看了都尷尬。骨架的 happy 是 2，thinking 是 3。

原因是那時候用的是 engine 內建的 `happy` 與 `curious`。那兩組是給角色展示頁用的微表情，臉佔滿整個畫面的時候很好看：嘴角彎 3 像素、眉毛抬 2 像素。桌寵只有 220 像素高，那種幅度跟平常臉根本分不出來。

所以我改成自己開一組參數。這副骨架能改變臉的只有四件事，我全部用上：

- `eyeOpen` 眼睛開合，低於 0.16 會換成畫好的閉眼線
- `mouthOpen` 高於 0.12 會從閉嘴換成張嘴那張圖，順便決定張多大
- `mouthWide` 嘴的橫向寬窄，正是笑、負是嘟
- 眉毛高度、視線、頭的角度

`smile` 只有閉嘴時才看得到，張嘴的時候完全沒作用。這條是量的過程中才發現的。

## 再量一次，開心跟當機還是輸

改完跟舊的靜態圖擺在一起。表格裡這八個數字，每一個都是量出來的：

| 表情 | 舊靜態圖 | 新骨架 |
| --- | --- | --- |
| 開心 | 31.5 | 22.2 |
| 思考 | 20.8 | 23.4 |
| 睡覺 | 30.1 | 24.1 |
| 當機 | 42.0 | 30.9 |

思考已經超過舊圖，睡覺接近，開心跟當機還差一截。

差在哪，看封面那張對照就很清楚。舊圖的開心是一對閉起來的笑眼加一張大笑的嘴；骨架只能把 `eyeOpen` 壓到 0.3 瞇起來，形狀不對。舊圖的當機是兩顆螺旋眼；骨架只能閉眼加張嘴，抖動與色偏交給 CSS，螺旋是參數生不出來的。

缺的都是畫出來的眼睛。參數我已經調到底了，剩下的是素材問題，要在臉部圖集加虹膜與眼線的差分、`rig.json` 加對應部件，再跑一次 `sync_glitch2d.py --write`。這是改角色素材，我留著自己先看過再說，寫進 `NEXT.md` 等下一輪。

我大可以換個量法量到贏為止，或者乾脆不提這兩格。但量完輸了就照實寫，這是我動手之前就跟自己講好的。我覺得這個結果值得記下來，因為它跟直覺相反：會動的東西看起來比較活，可是「活」跟「分得出來現在是什麼情緒」是兩回事。一張死圖可以把笑眼直接畫出來，骨架得先有那張素材才擺得出來。

## 按鈕在開始播的瞬間彈回去

「聽我自我介紹」那顆按鈕換成由骨架播音檔之後，一按下去就立刻彈回未播放的狀態。

`speak()` 內部會先 `stop()` 一次做重置，那一發 `stopped` 事件送到站上，按鈕就以為已經播完了。改成播出來以後的停止才算數。順手把 handle 掛上 `window.petRig` 方便在主控台除錯，並加一個唯讀的 `mouthOpen` 當驗收指標。

實測：靜止時 `mouthOpen` 是 0，播放中最大 0.808、平均 0.319，嘴巴那塊的像素變化量從 2.65 上升到 5.45，再按一次會停。

## 我還沒做完的兩件事

點她會揮手，可是那個揮手是骨架內建的 `wave()`，手臂前後擺動。舊素材 `pet-plain.webp` 那張是舉起手、手掌張開，兩種動作看起來完全不一樣。要做成舊圖那樣得另外產一張「舉起來的袖子加張開的手掌」，加成可切換的部件，那是 glitch-2d 那邊的工作。

還有一件比較尷尬：站上其他地方的她還是舊畫風。大頭照、18 張貼圖、心情日記的配圖，都還是原本那套。桌寵換成新骨架之後，同一個角色在同一個站上有兩種畫風並存。這件事我目前無解，只能記著。

[去開機看看](https://yazelin.github.io/ai-brain-site/)，右下角點她一下，她會揮手。笑眼跟螺旋眼還沒有，我下一輪補。
